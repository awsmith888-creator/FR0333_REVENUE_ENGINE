## HOME / PURPOSE

This is the resume point for the working repository gate added to the PR #65 branch. It validates that the indexed Green Dot documents exist, have readable Markdown titles, keep their tab sequence intact, preserve the four probability PINs, and resolve their local certification-file references. It emits a JSON receipt bound to the tested commit SHA and uploads that receipt as a workflow artifact.

This is a repository-content check. It does not run the proposed ten instruction cases, generate or inspect ten images, test a live service, calibrate probability, certify runtime GREEN, or authorize promotion.

## WHAT IS PLACED INTO THE ENGINE

1. `scripts/validate_green_dot_tabs.py` — dependency-free Python validator and JSON receipt writer.
2. `.github/workflows/fr0333-green-dot-certification-validate.yml` — pull-request and manual workflow scoped to these certification records and the validator.
3. This append-only WRITE-ME — numbered tabs, pins, run instructions, and explicit authority limits.

The validator checks the nine indexed Markdown files, validates each declared TAB sequence, verifies local certification-file paths, confirms `PIN.0001` through `PIN.0004` remain in the probability extension, and requires each indexed record to retain an explicit HOLD/PENDING boundary.

## PINS

- `PIN.VALIDATION.0001 EXACT.HEAD`: a PASS applies only to the commit SHA recorded in the receipt.
- `PIN.VALIDATION.0002 REPOSITORY.SCOPE`: the job checks document/index integrity only; it is not runtime evidence.
- `PIN.VALIDATION.0003 RECEIPT.BINDING`: retain the workflow run ID, commit SHA, logs, and uploaded JSON receipt together.
- `PIN.VALIDATION.0004 REGRESSION.SEPARATION`: instruction and image regression results require their own executed cases and artifacts.
- `PIN.VALIDATION.0005 HUMANLOCK`: CI cannot grant HumanLock approval or promote GREEN.
- `PIN.VALIDATION.0006 FAILURE.PRESERVATION`: a failed check remains visible; correct the source, rerun against the new exact head, and retain both receipts.

## RUN / RECEIPT

Local repository check:

```bash
python scripts/validate_green_dot_tabs.py --receipt /tmp/green_dot_repository_validation_receipt.json
```

GitHub pull requests run the same validator when an indexed certification file, the validator, or its workflow changes. A passing run uploads `green-dot-repository-validation-<commit SHA>` with the JSON receipt. The receipt states `runtime_execution=NOT_TESTED`, `instruction_regression=NOT_TESTED`, `image_regression=NOT_TESTED`, and `humanlock_promotion=NOT_AUTHORIZED`.
